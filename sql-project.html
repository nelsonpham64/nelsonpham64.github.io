Project Overview

For this project, we designed a new relational database structured around five core entities: ACCOUNT, BOOK, CHECKOUT, TRANSACTION, and EMPLOYEE.

This system is designed to improve data organization, reduce redundancy, and streamline routine tasks such as inventory updates and checkout verification. The schema follows proper normalization principles and includes comprehensive constraints, indexes, and foreign key relationships.

Database Entities

ACCOUNT Table

Stores user account information including credentials, contact details, and account status. Implements primary key constraints and proper indexing for efficient queries.

  • Primary Key: Account_ID
  • Key Fields: Username, Email, Phone, Registration_Date
  • Indexes: Email, Username for fast lookups

BOOK Table

Contains comprehensive book information including ISBN, title, author relationships, genre, publication details, and inventory quantities.

  • Primary Key: Book_ID
  • Foreign Key: Author_ID (references AUTHOR table)
  • Key Fields: ISBN, Title, Genre, Quantity_Available
  • Indexes: ISBN, Title, Author_ID for search optimization

CHECKOUT Table

Manages the checkout process, tracking which books are borrowed by which accounts, along with due dates and return status.

  • Primary Key: Checkout_ID
  • Foreign Keys: Account_ID, Book_ID
  • Key Fields: Checkout_Date, Due_Date, Return_Date, Status
  • Indexes: Account_ID, Book_ID, Due_Date

EMPLOYEE Table

Stores employee information for staff managing the system, including role assignments and contact information.

  • Primary Key: Employee_ID
  • Key Fields: Name, Role, Email, Hire_Date
  • Indexes: Email for quick staff lookups

AUTHOR Table

Maintains author information separate from books to support many-to-many relationships and reduce data redundancy.

  • Primary Key: Author_ID
  • Key Fields: First_Name, Last_Name, Biography
  • Indexes: Last_Name, First_Name for author searches

Key Design Features

  • Normalization: Database follows Third Normal Form (3NF) to eliminate data redundancy and ensure data integrity
  • Referential Integrity: Foreign key constraints maintain relationships between tables and prevent orphaned records
  • Performance Optimization: Strategic indexes on frequently queried columns for fast data retrieval
  • Data Constraints: NOT NULL constraints, primary keys, and check constraints ensure data quality
  • Mock Data: Populated tables with realistic test data to validate schema design

Technical Implementation

The database was implemented using SQL Server with careful attention to:

  • Primary key and foreign key constraint definitions
  • Index creation for performance optimization
  • NOT NULL constraints for data integrity
  • Proper data type selection for each field
  • Relationship mapping between entities
